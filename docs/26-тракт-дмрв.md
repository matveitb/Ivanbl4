# Тракт ДМРВ найден по коду: KFPU, KFKHFM, WDKUGDN

Всё, что оставалось ненайденным в воздушном тракте, найдено. Не
выравниванием по чужому дамосу -- этих карт в нём нет вовсе, -- а по
коду, с подсказкой от Funktionsrahmen о том, какие у них входы.

## Что дал ФР

Сигнатуры, без которых поиск был слепым:

| имя | входы | тип |
|---|---|---|
| `KFKHFM` | NMOT x RL | карта |
| `KFPU` | NMOTKOR x WDKBA | карта |
| `KFPUNW` / `KFPUSU` / `KFPUSUNW` | то же, варианты по sumode | карта |
| `WDKUGDN` | NMOT | кривая |
| `SNM12FEUB` | NMOT | опорные точки для `WDKUGDN` |

Плюс замечание из ФР: *Pulsation correction initially neutralised (set
KFPU to 1)* -- то есть это множитель около единицы. Это и стало
признаком для поиска.

## Новый инструмент: hdrscan

Часть карт лежит не «голым телом плюс отдельная ось», а одним куском:

```
[nx][ny][ось X, nx значений][ось Y, ny значений][данные, nx*ny]
```

Указатель в коде ведёт на ЗАГОЛОВОК, поэтому поиск по адресу данных их не
находит -- на этом я один раз уже споткнулся с `KFLF`.

`tools/hdrscan.py` перебирает сегмент и принимает место за заголовок,
только если сходится всё сразу: обе оси строго возрастают, блок целиком
помещается в сегмент, данные не вырождены. Строгая монотонность двух осей
подряд на случайных данных почти не встречается, поэтому ложных
срабатываний мало.

Нашлось **56 заголовочных карт** в нашей прошивке и 51 в ВАЗовской.

## Развязка по коду

Среди них оказались три карты 14x14 со значениями вокруг 128, то есть
около единицы при масштабе 1/128. Указатели на них нашлись по коду, и
рядом обнаружился диспетчер:

```
842B74   cmpb  RL4, #0x2
842B76   jmpr  cc_EQ, 0x842b94       ; режим 2
842B78   cmpb  RL4, #0x3
842B7A   jmpr  cc_EQ, 0x842baa       ; режим 3
842B7C   jmpr  cc_UC, 0x842bc0       ; режим 1
842B7E   mov   r12, #0x1485          ; по умолчанию
842B82   movbz r13, 0x88d2           ; вход 1
842B86   movbz r14, 0x89f3           ; вход 2
842B8A   calls 0x007312
842B8E   movb  0x88d1, RL4           ; результат
...
842BD4   mov   r12, #0x10fd          ; ВСЕГДА, другая карта
842BD8   movbz r13, 0xf89e           ; индекс нагрузки
842BDC   movbz r14, 0xf86b           ; обороты
842BE0   calls 0x007312
842BE4   movb  0x88d0, RL4
```

Четыре карты с одинаковыми входами, выбираемые по режиму, плюс пятая с
другими входами, читаемая всегда. Это буквально структура из ФР.

| адрес | данные | режим | имя | значения /128 |
|---|---|---|---|---|
| 0x11485 | 0x114A3 | по умолчанию | **`KFPU`** | 0.922..1.086 |
| 0x111DF | 0x111FD | 1 | `KFPUSU` | 0.945..1.133 |
| 0x112C1 | 0x112DF | 2 | `KFPUNW` | **ровно 1.000** |
| 0x113A3 | 0x113C1 | 3 | `KFPUSUNW` | **ровно 1.000** |
| 0x110FD | 0x1111B | всегда | **`KFKHFM`** | 1.000..1.078 |

### Внутренняя проверка, которая не может совпасть случайно

Оба варианта с `NW` в имени относятся к управлению фазами
газораспределения. **Фазовращателя на S6D нет** -- это было установлено
раньше и по другому поводу. И обе эти карты оказались **строго в
единицах, во всех 196 ячейках каждая**, тогда как две другие несут
по два десятка различных значений.

То есть код, ФР и железо сошлись в одной точке. Закреплено тестом
`tests/test_hfm.py`.

## KFPU, 0x11485

Множитель коррекции расхода по пульсациям, обороты x угол дросселя,
делить на 128.

Обороты: 600, 800, 1000, 1400, 1800, 2200, 2600, 2920, 3320, 3800, 3920,
4200, 5000, 6000.

Дроссель, %: 0, 5.1, 10.2, 14.8, 18.4, 24.6, 30.9, 37.1, 43.4, 49.6,
55.1, 61.3, 73.8, 99.2.

Фрагмент:

| об/мин \ дроссель | 0 % | 10 % | 25 % | 50 % | 99 % |
|---|---|---|---|---|---|
| 600 | 0.969 | 0.969 | 0.969 | 0.969 | 0.977 |
| 1800 | 0.930 | 0.961 | 1.000 | 1.016 | 1.008 |
| 2920 | 0.930 | 0.945 | 1.047 | 1.062 | 1.055 |
| 6000 | 1.000 | 0.945 | 1.047 | 1.086 | 1.086 |

**Что это значит для провала.** Коррекция скромная: от 0.92 до 1.09, то
есть плюс-минус восемь процентов. В полосе 1800-3300 при среднем и
большом открытии дросселя расход поправляется **вверх** на 3-6 %. Этого
мало, чтобы объяснить провал на секунду-две. Как самостоятельная причина
карта не годится -- но теперь она хотя бы видна и правится.

## WDKUGDN, 0x15B40

Угол дросселя, при котором достигается 95 % максимально возможного
наполнения. Двенадцать точек u16, масштаб 100/65536, ось `SNM12FEUB` на
0x100D4.

| об/мин | 800 | 1440 | 2520 | 3520 | 4520 | 5520 | 6520 |
|---|---|---|---|---|---|---|---|
| % дросселя | 11.3 | 19.0 | 24.6 | 30.0 | 35.4 | 38.4 | 43.0 |

Растёт по оборотам, как и должно: чем выше обороты, тем шире надо
открыть дроссель, чтобы наполнить цилиндр. Адрес -- px5ns03d 0x1584C
плюс 756, а этот сдвиг доказан побайтовым совпадением `KLAF` и
подтверждён на `KFMSNWDK`.

**Её крутили четверо.** MPower сделал плоской 15.0 % на всех оборотах,
Xoptim и Xstart занизили, L завысил. Плоские 15 % означают, что ЭБУ
считает дроссель открытым «достаточно» уже с четверти хода на любых
оборотах -- это заметно меняет оценку отношения давлений в дроссельной
модели.
