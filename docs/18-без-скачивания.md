# Как найти дамос, не скачивая 240 гигабайт

## Идея

Оглавление архива -- это килобайты, а HTTP умеет забирать произвольный
кусок файла заголовком `Range`. Значит список имён внутри гигабайтного
архива читается, если скачать от него сотую долю процента.

| Формат | Запросов | Сколько качается |
|---|---|---|
| ZIP | 2 | хвост 64 КБ + оглавление |
| 7z, заголовок открытый | 2 | 32 байта + заголовок |
| 7z, заголовок сжат | 3 | плюс упакованный заголовок, распускается LZMA на месте |
| RAR4/RAR5 | по блокам | только заголовки, данные перешагиваются |

Замер на пробе: ZIP на 4 МБ -- **2 запроса, 96 КБ**. Накладные расходы
почти не зависят от размера архива, поэтому на гигабайтном файле это те
же ~96 КБ, то есть **0.009 %**. Все 240 архивов -- порядка 20-30 МБ
вместо 240 ГБ.

## Порядок работы

```
# 1. получить прямые ссылки на все архивы публичной папки
python3 tools/cloudmail.py 'RiNt/JAGmbYraM/База прошивок новая/WinOLS/Дамосы 800 гигабайт!' \
    --recurse --out ссылки.txt

# 2. прочитать оглавление каждого, ничего не скачивая
python3 tools/remotels.py --list ссылки.txt \
    --grep '1037368793|0261208504|FBH3ID60|391102X3350|M7\.9\.7' \
    --out найдено.txt

# 3. вытащить только нужный файл из нужного архива (ZIP)
python3 tools/remotels.py 'ССЫЛКА-НА-АРХИВ' --get 'путь/1037368793.dam' --dest firmware/

# 4. оценить, стоит ли он того
python3 tools/damoscore.py firmware/1037368793.dam
```

Перед большим прогоном имеет смысл проверить один архив:

```
python3 tools/remotels.py --probe 'ССЫЛКА'
```

Печатает формат, размер и главное -- отвечает ли сервер на `Range`.
Если `Range НЕТ`, весь способ не работает и качать придётся целиком.

## Что проверено, а что нет

Проверено на локальном сервере с поддержкой Range, закреплено в
`tests/test_remotels.py`:

* ZIP -- оглавление и **побайтовое совпадение** вытащенного файла с
  оригиналом (1 139 382 байта сошлись);
* ZIP многотомный -- распознаётся и сообщает об этом, а не выдаёт мусор;
* 7z -- оглавление и при открытом, и при сжатом заголовке (7z сжимает
  заголовок по умолчанию, без распаковки LZMA способ был бы бесполезен);
* RAR5 -- разбор заголовков на образце, собранном по спецификации.

**Не проверено:** обращения к API самого cloud.mail.ru. Из среды, где
это писалось, домен закрыт сетевой политикой (403 на CONNECT), поэтому
`tools/cloudmail.py` написан по документированной схеме API, но вживую
не запускался. Если ответ окажется другим -- запустите с `--raw`,
скрипт напечатает сырой JSON.

Также не проверено, отдаёт ли раздающий узел mail.ru куски по `Range`.
Скорее всего да -- на этом держится перемотка видео и докачка, -- но
пока не попробуете, это предположение. `--probe` отвечает на вопрос за
один запрос.

## Подводные камни

**Многотомный архив.** Если файлы названы `part001.rar`, `part002.rar`
и так далее, то это не 240 архивов, а ОДИН архив, разрезанный на 240
кусков. Тогда:

* у ZIP оглавление лежит в последнем томе -- читать надо его;
* у RAR заголовки файлов раскиданы по томам, оглавление собирается
  обходом с первого тома;
* а вот вытащить один файл уже не получится, если он пересекает границу
  тома или если архив solid -- в solid-архиве файлы распаковываются
  только подряд с начала.

`remotels` распознаёт многотомный ZIP и говорит об этом прямо, а не
выдаёт правдоподобный мусор.

**Пароль.** Зашифрованные имена файлов (`-mhe=on` у 7z, `-hp` у RAR)
читаться не будут. Тогда виден только факт шифрования.

## Если ничего из этого не взлетит

Остаётся самый дешёвый вариант, и он не требует ни байта трафика:
**прислать список имён этих 240 архивов** -- скриншотом или копипастом
из браузера. Если они названы осмысленно, нужный определяется по
имени, и качать придётся ровно один.
