# Пошаговая методика разметки

Порядок важен: каждый шаг сужает поиск для следующего.

## Шаг 0. Проверить образы

```bash
python3 tools/fwinfo.py firmware/stock.bin
```

Смотрим:

- **Размер.** Должен быть ровно 0x40000 (256 КБ) или 0x80000 (512 КБ).
  Иначе разбираемся с заголовком дампа, прежде чем идти дальше.
- **Карта регионов.** Энтропия 5.8–7.2 бит/байт — код; 3.2–5.8 —
  калибровки и таблицы; сплошные `0xFF` — стёртая флеш.
  Инструмент сам печатает готовые строки `--range 0x... 0x...`
  для калибровочных областей.
- **Строки.** Ищем номер блока Bosch (`0261...`), номер ПО (`1037...`),
  номер калибровки. Это идентифицирует прошивку и пригодится в WinOLS.

Прогоняем для всех трёх файлов и сравниваем — регионы должны совпадать.

## Шаг 1. Дифф двух csok — карты зажигания

Это самый результативный шаг. Делайте его первым.

```bash
python3 tools/fwdiff.py firmware/csok1.bin firmware/csok2.bin \
    --identify --dump --out out/diff_csok.json
```

Раз файлы отличаются только углами зажигания, каждая изменённая область —
это тело карты зажигания. `--identify` достраивает заголовок и оси,
`--dump` печатает обе таблицы и матрицу разностей.

Что читать в выводе:

- строки `карта @0x... 3d 16x16 осьu8 данныеu8` — **готовая разметка**,
  адрес заголовка можно прямо вносить в WinOLS;
- `Δ[-6..+6]` — разброс правок. Для углов зажигания при типичном масштабе
  0.75 °/ед. это примерно ±4.5 градуса — правдоподобно;
- области, помеченные `контрольная сумма?` — ячейки сумм;
- `структура не распознана` — вероятно карта с общей осью либо иная
  раскладка; см. «Разбор нераспознанных областей» ниже.

Основные карты зажигания в M7.9.7 обычно: основная (по нагрузке и оборотам),
карта для частичных нагрузок, карта холостого хода, коррекции по температуре.
Ожидайте несколько областей, а не одну.

## Шаг 2. Дифф сток против csok

```bash
python3 tools/fwdiff.py firmware/stock.bin firmware/csok1.bin \
    --identify --out out/diff_stock.json
```

Показывает **всё**, что калибровщик менял относительно стока: зажигание,
топливо, лямбда, отсечка, возможно отключённые диагностики. Каждая область —
кандидат в именованную карту.

## Шаг 2а. Голые таблицы

Если `fwdiff --identify` пишет «структура не распознана», а область явно
похожа на таблицу — это карта без заголовка. Ищите её `gridscan`-ом:

```bash
python3 tools/gridscan.py firmware/stock.bin --range 0x10500 0x10600
```

Именно так найдены все три карты зажигания FBH3ID60. Инструмент выдаёт
адрес, ширину и высоту; проверить глазами можно через `showmap.py`.

## Шаг 3. Полное сканирование

```bash
python3 tools/mapscan.py firmware/stock.bin --out out/maps_stock.json
```

Находит карты, которые никто не трогал и потому в диффах не видны.

Если ложных срабатываний много — сужайте:

```bash
# только калибровочная область из шага 0
python3 tools/mapscan.py firmware/stock.bin --range 0x18000 0x20000 \
    --min-score 0.65 --out out/maps_cal.json

# только крупные карты
python3 tools/mapscan.py firmware/stock.bin --min-cells 32 --min-smooth 0.7
```

Полезные фильтры:

| Ключ | Смысл |
|---|---|
| `--min-smooth` | Порог гладкости. 0.55 по умолчанию; 0.7+ отсекает мусор жёстче |
| `--min-score` | Порог итоговой оценки |
| `--min-cells` | Минимум ячеек; 32+ оставит только серьёзные карты |
| `--max-dim` | Максимум точек на ось; 32 по умолчанию |
| `--kinds 3d` | Искать только таблицы, без кривых |

Колонка `XREF` — сильный фильтр: реальные карты почти всегда имеют
несколько ссылок из кода.

## Шаг 4. Свести всё вместе

Диффы дают **достоверные** карты (мы знаем, что их правили). Сканер даёт
**вероятные**. Пересечение — самое надёжное.

Практический приём: карта, найденная и диффом, и сканером, с оценкой выше
0.7 и ненулевым XREF — можно вносить в проект не глядя.

## Шаг 5. Именование

Создайте `out/names.json`:

```json
{
  "0x18000": "IGN_MAIN_основное_зажигание",
  "0x1813C": "IGN_PART_частичные_нагрузки",
  "0x18286": "IGN_IDLE_холостой_ход"
}
```

и подставьте при экспорте:

```bash
python3 tools/a2lgen.py out/maps_stock.json --names out/names.json \
    --a2l out/stock.a2l --csv out/stock.csv
```

Как понять, что есть что, не имея дизассемблера:

- **Зажигание** — найдено диффом двух `csok`. Значения обычно растут с
  оборотами и падают с нагрузкой.
- **Топливо / VE** — крупные карты 16x16, значения растут с нагрузкой.
- **Лямбда** — узкий диапазон значений вокруг стехиометрии, часто с
  обогащением на полной нагрузке (край карты уходит вниз).
- **Отсечка по оборотам** — короткая кривая, значения в районе 6000–6800
  при масштабе оборотов.
- **Прогрев** — кривая по температуре, монотонно убывающая.

Окончательное подтверждение даёт только реверс кода либо логи с реального
двигателя. Не выкатывайте на машину догадки.

## Шаг 6. Контрольные суммы

Перед прошивкой изменённого файла:

```bash
python3 tools/checksum.py firmware/stock.bin --align 0x1000
```

и обязательно сверьтесь с ячейками, которые `fwdiff` пометил как
`контрольная сумма?` — они надёжнее, потому что получены из двух заведомо
рабочих прошивок.

Проверить гипотезу:

```bash
python3 tools/checksum.py firmware/csok1.bin --verify 0x7FFF0 0x0 0x7FFF0
```

Инструмент печатает, совпадает ли записанное значение с суммой байт или слов.

На практике для M7.9.7 проще пересчитывать суммы штатным чексуммером
(WinOLS умеет это для многих проектов, есть и отдельные утилиты). Наши
инструменты нужны, чтобы **понять**, где суммы лежат и какой регион
покрывают.

## Разбор нераспознанных областей

Если `fwdiff` пометил область как `структура не распознана`:

1. Увеличьте окно поиска заголовка: `--max-back 400`.
2. Ослабьте ограничения на размерность: карта может быть больше 32 точек —
   правьте `--max-dim` в `mapscan` и проверьте область вручную.
3. Возможно, это карта с **общей осью** — тело лежит отдельно от осей.
   Определите размерность по размеру области: 256 байт = 16x16 при `u8`,
   128 байт = 16x8 или 8x16, и так далее. Дальше подбирайте разбиение так,
   чтобы матрица разностей выглядела осмысленно (`--dump`).
4. Область может быть вообще не картой — например, правка одиночной
   константы (порог, флаг) или блок диагностики.
