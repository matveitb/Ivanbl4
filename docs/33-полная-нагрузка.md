# Полная нагрузка: когда она признана и насколько тогда обогащать

Владелец попросил разобраться с остатками — с теми правками тюнеров,
которые не попадали ни в одну известную карту. Разбор вывел на цепочку,
которую правят **все десять авторов без исключения**, и попутно исправил
мою собственную поспешность.

## Поправка: «лямбда по оборотам» — это обогащение полной нагрузки

Вчера я нашёл две кривые на `0x1955B` и `0x19568`, разобрал, как они
читаются, и написал: «обогащают во всём диапазоне оборотов». Про
диапазон верно, а вот **при каком условии кривая вообще читается — я не
посмотрел**. А там стоит замок:

```
8551A4   jnb   0xfd48.11, 0x8551e8     ; НЕ полная нагрузка ->
8551E8   mov   r4, #0x1000             ; запрос ровно 1.000
8551EC   mov   0x9880, r4
```

Без признака полной нагрузки запроса нет вовсе. И имя у кривых есть:
в дамосе лежит массив указателей `KLLAMFA_0_A` / `KLLAMFA_1_A` — две
кривые по шесть точек, множитель `0.0078125`, описание **full load
enrichment**. Сходится всё: число точек, множитель, парность, и главное —
условие чтения. Имена `CURVE_1955B` / `CURVE_19568`, которые я дал от
безымянности, отозваны.

## Кто ставит этот признак

Та же схема с таблицей указателей, что и у `KLLAMFA`:

```
8506BE   mov   r12, [r5+#0x5f4c]   ; смещение кривой
8506C2   mov   r13, [r5+#0x5f4e]   ; страница
8506C6   movbz r14, 0xf89e         ; обороты
8506CA   calls 0x833a00
8506CE   movbz r5, 0x89f3          ; УГОЛ ДРОССЕЛЯ
8506D2   cmp   r5, r4
8506D6   bset  0xff10.6            ; выше порога
8506DC   bmov  0xfd48.11, 0xff10.6 ; -> признак полной нагрузки
```

Таблица: `0x15F4C = {0x0FD7, 0x0206}`, `0x15F50 = {0x0FE4, 0x0206}`.
В дамосе она зовётся `WDKVLN_0_A` / `WDKVLN_1_A` — «Throttle valve angle
threshold for full load detection». Ровно то, что делает код.

Тут же рядом, на `0x8506E0`, тем же способом читается `WDKSLN` и ставит
`0xFD48.10` — признак холостого хода. Два порога-брата: один снизу,
другой сверху.

## Вся цепочка

| шаг | что | где |
|---|---|---|
| 1 | угол дросселя выше `WDKVLN`(обороты) → признак полной нагрузки | `0x8506BE` |
| 2 | счётчик `0x9882` дорастает до задержки из `0x1B894` | `0x8551B0` |
| 3 | читается `KLLAMFA`(обороты), ×32 → `0x9880` | `0x8551D0` |
| 4 | минимум против `KFLBTS` и остальных запросов | `0x85333E`, `0x853426` |

Вариант кривой (0 или 1) в шагах 1–3 выбирает `0xF87A` — тот же
переключатель, что выбирает вариант `WDKKOAN` у кондиционера.

## Что правят авторы

| | `WDKVLN[0]`, % дросселя | `KLLAMFA[0]`, лямбда |
|---|---|---|
| сток | 65.1 на всех оборотах | ровно 1.000 — обогащения нет |
| csok, csok v2 | 58.0 | 0.906…0.859 |
| startpower | 40.0…59.2 по оборотам | 0.906…0.859 |
| MPower | **20.0** на всех оборотах | 1.023 — беднее стока |
| L | 4.3 / 25.5 / 50.2 | 0.906…0.805 |
| Xoptim, Xstart | 9.8…49.0 | 0.887…0.883 |

**Порог полной нагрузки тронули все десять.** Это единственная запись во
всей прошивке с таким счётом — даже `KFLBTS` правят не все.

Смысл правки виден сразу: опустить порог — значит признавать полную
нагрузку раньше, с меньшего нажатия педали. У MPower полная нагрузка
начинается с пятой части хода, при этом сама лямбда выставлена **беднее**
стока — то есть у него это не обогащение, а перевод мотора в режим полной
нагрузки как таковой. У остальных порог опущен вместе с обогащением.

## Заодно: пороги лямбда-регулирования

Сдвиг дамоса в области `0x18Axx` нулевой, и это проверено, а не принято:
у четырёх записей есть ссылка из кода, и вход совпал с именем.

| имя | адрес | значение | код |
|---|---|---|---|
| `RLLRTMO` | `0x18AC9` | 99.75 % | вход `0x8AB4` — **температура ОЖ**, ровно как в имени «on tmot» |
| `RLLRUN` | `0x18ADA` | 2.25 % | вход `0xF89E` — **обороты**, ровно как в имени «above nmot» |
| `TARAU` | `0x18AE2` | 60 °C | `cmpb RL4, 0x0ae2` |
| `TLRHS` | `0x18AE4` | 2.5 с | `movb RL4, 0x0ae4` |
| `TMRA1`, `TMRA2` | `0x18AE5` | 15 °C | `movbz r12, 0x0ae5` |

## Ошибка, которую поймала эта же работа

У `RLLRTMO` ось по температуре, и она читалась **17.25…147** вместо
**−30.75…99**: сборщик применял к оси множитель, но не вычитал смещение —
в `axis_obj()` стоял жёсткий ноль. На осях оборотов это незаметно, там
смещения нет, поэтому ошибка и дожила до первой температурной оси.
Поправлено, проверка закреплена поимённо.

## Итог

Покрытие правок выросло с **95.7 %** до **96.6 %**: осталось 134 байта в
24 участках. Карт 604, русских названий 282.
