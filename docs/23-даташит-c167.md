# Что дал даташит C167 и почему БЦН/ПЦН в нём нет

## Сразу честно: это не Funktionsrahmen

Присланный файл -- **Infineon C167CR/C167SR Data Sheet V3.3, февраль
2005**, 89 страниц. Это описание микроконтроллера: выводы, регистры,
электрические параметры, тайминги.

**БЦН и ПЦН в нём быть не может.** Это калибровочные понятия Bosch, а не
свойства кристалла. Их описывает Funktionsrahmen, а он документ другой.

Но даташит закрыл три вопроса, которые до него висели.

## 1. Потолок метода теперь документирован, а не предположен

Вчера я вывел из кода, что 1647 вызовов уходят в 122 процедуры, которых
в образе нет, и предположил внутреннюю память. Даташит, раздел 3.1:

> The C167CR incorporates 128/32 Kbytes of on-chip **mask-programmable
> ROM** for code or constant data. **The lower 32 Kbytes of the on-chip
> ROM can be mapped either to segment 0** or segment 1.

Сверка с кодом:

| | |
|---|---|
| процедур в сегменте 0 | 122 |
| диапазон адресов | 0x000700 .. 0x007F7A |
| все внутри нижних 32 КБ | **да** |
| занимают | **30.1 КБ из 32** |

Совпадение точное. Библиотечные процедуры Bosch лежат в масочном ПЗУ
самого микроконтроллера. Никаким чтением внешней флеш-памяти их не
достать -- ни этим дампом, ни любым другим.

## 2. Карта регистров: было 95 по памяти, стало 209 по документу

`tools/gen_sfr.py` извлекает таблицу 8 из раздела 3.15 в
`data/c167_sfr.json`. Сам PDF в репозиторий не кладётся -- он чужой;
кладётся извлечённая фактическая таблица и скрипт, чтобы её можно было
получить заново.

**156 SFR + 53 ESFR.** Формула короткого адреса `(адрес - база) / 2`
проверена на всей таблице разом: **207 из 209 сходятся**. Два расхождения
выписаны, а не заминаются:

```
T7IC: 0xF17A даёт 0xBD, в таблице 0xBE
T8IC: 0xF17C даёт 0xBE, в таблице 0xBF
```

Оба соседние и оба смещены на единицу -- почти наверняка опечатка в самой
таблице даташита. Формула верна.

## 3. ZEROS: находка из кода подтверждена документом

Вчера `mov 0xf8a0, 0xff1c` выглядело бессмыслицей, пока я не догадался
по байтам `F6 8E`, что 0xFF1C -- регистр постоянных нулей, и это
**обнуление расхода воздуха**. Даташит:

```
ZEROS    b FF1CH    8EH    Constant Value 0's Register (read only)
ONES       FF1EH    8FH    Constant Value 1's Register (read only)
```

Короткий адрес `8EH` -- ровно тот байт `8E`, что стоял в инструкции.
Догадка по коду и документ сошлись независимо.

Заодно подтверждён `ADCON FFA0H D0H` -- тот самый 0xD0, который я
посчитал по формуле, когда поиск по слову 0xFFA0 давал ноль попаданий.

## 4. Время преобразования АЦП

Из таблицы 14: все наблюдённые в коде значения `ADCON` дают
ADCTC = 00 и ADSTC = 00. По расчёту самого даташита при 25 МГц это
**7.8 мкс на канал**. Полный обход шестнадцати каналов -- около 125 мкс.

Для спора про провал это цифра по делу: датчик опрашивается на четыре
порядка быстрее, чем длится провал. Запаздывание опроса тут ни при чём.

Битовые поля `ADCON` (номер канала, режим) в Data Sheet не расписаны --
они в User Manual, документе другом. Поэтому какой канал соответствует
ДМРВ, отсюда не определить.

## 5. Ниточка: счётчик до двадцати

С полной разметкой регистров стал читаем механизм, который обнуляет
расход. Флаг -- бит 10 ячейки 0xFD68: шесть мест взводят (`bset`), одно
сбрасывает (`bclr`). Так выглядит флаг запрета, а не режим работы.

Взводится он не сразу:

```
85F124   addb  RL4, #0x1        ; счётчик +1
85F126   movb  0x8a9f, RL4      ; сохранить в 0x8A9F
85F136   movbz r4, 0x8a9f
85F13A   cmp   r4, #0x14        ; сравнить с 20
85F13E   jmpr  cc_SLT, 0x85f144 ; меньше двадцати -- мимо
85F140   bset  0xfd68.10        ; ДОСЧИТАЛО -- взвести
85F142   bclr  0xfd68.11        ; и сбросить соседний бит
```

Условие должно продержаться **двадцать проходов подряд**, и только тогда
расход воздуха обнуляется.

**Чего отсюда делать НЕЛЬЗЯ.** Соблазнительно посчитать: если цикл
десятимиллисекундный, двадцать проходов это 200 мс, если
стомиллисекундный -- две секунды, и вот он провал. Но частота этого
цикла из статического разбора не следует: она задана планировщиком
задач, а тот вызывается из процедур, лежащих в масочном ПЗУ, которого у
нас нет (см. пункт 1).

Так что это **ниточка, а не ответ**. Проверяется она замером, а не
чтением кода: лог расхода воздуха на провале против расчётной таблицы из
`tools/expect_maf.py`. Если расход в провале падает почти до нуля --
ниточка та. Если держится около расчётного -- механизм ни при чём.

## Что всё ещё нужно для БЦН и ПЦН

Даташит их не содержит и содержать не мог. Нужен один из:

* **Funktionsrahmen** -- даст имена и связи, но не адреса;
* **дамос от M7.9.7** -- даст адреса напрямую (`docs/17-поиск-дамоса.md`);
* **модуль CTP KIA 013** -- готовая раскладка (`docs/21-разметка-c167.md`).
