# Топливо: где оно правится на самом деле

## Короткий ответ

В M7.9.7 нет одной «карты топлива». Впрыск считается из модели наполнения и
целевой лямбды, поэтому топливо правят в трёх местах. Сравнение одиннадцати
прошивок одной базы показывает, что реально используются только два из них.

| Что | Адрес | Меняли |
|---|---|---|
| Кривые топливной коррекции по температуре | `0x1955B`, `0x19568` | **все без исключения** |
| `KFLBTS` — целевая лямбда защиты компонентов | `0x19636` | 4 варианта из 11 |
| `KRKTE` — константа форсунки | `0x19485` | **никто** |
| `TEMIN` / `TEMINVA` — минимальное время впрыска | `0x15E44` / `0x15E46` | **никто** |
| `KFLF` — лямбда частичных нагрузок, 16×12 | `0x190EC` | **никто** |

Вывод, который стоит осознать: глобальные топливные константы не трогает
никто. Вся возня со смесью идёт через две шеститочечные кривые и через
лямбду защиты компонентов.

## Кривые топливной коррекции

Две одинаковые по структуре кривые по шесть точек, с общей осью.

```
0x1955B: счётчик 6, ось 0x1955C, данные 0x19562
0x19568: счётчик 6, ось 0x19569, данные 0x1956F
```

**Ось** — сырые значения `37 62 87 112 137 162`. При температурной шкале
M7.9.7 (× 0.75 − 48, подтверждена и DAMOS, и файлами `.b79`) это

```
-20.2   -1.5   +17.2   +36.0   +54.8   +73.5   °C
```

**Значения** — множитель:

```
физ = сырое * 0.001953125 + 0.75      (128 -> 1.000, шаг 0.195 %, диапазон 0.75…1.248)
```

### Откуда взялась шкала

Она не угадана, а зажата двумя независимыми условиями:

1. В стоке и в `Spectra ori_e3` вся кривая равна ровно **128** — значит 128
   это нейтраль, множитель 1.000.
2. Разница `csok` → `csok v2` составляет ровно **2 единицы** на всех шести
   точках. Калибровщик сказал, что эти прошивки отличаются по топливу
   «примерно на 0.3 %». Два шага дают **0.39 %**.

Среди всех пересчётов DAMOS ровно один удовлетворяет обоим условиям сразу:
`fak_ub_q0p0019_o0p75`. Шаг 0.78 % (самый частый множитель `fak_ub_b2`) дал
бы 1.56 % — вчетверо больше сказанного.

### Значения по прошивкам

| Прошивка | Кривая 1 (−20 … +73 °C) |
|---|---|
| сток, `Spectra ori_e3` | 1.000 везде — коррекции нет |
| `csok` | 0.977 … 0.965 |
| `csok v2` | 0.973 … 0.961 — на 0.39 % беднее `csok` |
| `MPower` | **1.006** равномерно — единственный, кто обогащает |
| `Spectra mod` | 1.000 на холодную → 0.963 на горячую |
| `Xstart` / `Xoptim` | 0.951 … 0.971 |
| `startpower`, `NI_startpower`, `FBH3ID60_L` | как `csok` |

Почти все авторы обедняют смесь на 2–5 %, и почти все — сильнее на прогретом
двигателе. `MPower` выделяется: он единственный слегка обогащает здесь, но
при этом полностью снял обогащение защиты компонентов в `KFLBTS`.

## Чего установить не удалось

**Имени переменной.** Испробовано семь путей, все пустые:

- перенос из DAMOS — по этому адресу ничего не отображается, область между
  M7.9 и M7.9.7 расходится (в px5ns03d по `0x19568` лежит `KFLBTS` 16×12,
  а не кривая);
- соседи по DAMOS в исходных адресах — в `0x19520…0x195C0` только `KFLBTS`;
- ссылки из кода по указателю (`mov rN, #0x955B`) — ни одной;
- ссылки через страничную адресацию DPP — только попадания в ОЗУ (записи,
  а не чтения флеша);
- поиск этой оси в образе px5ns03d — отсутствует;
- шеститочечных осей с такими значениями в файлах `.b79` нет;
- идентификаторы из `Yscale.dat` относятся к другим пакетам разметки.

Наиболее вероятная причина отсутствия ссылок: читающая процедура лежит в
**сегменте 0**, которого в дампе нет — там же, где и все процедуры
интерполяции (`0x0078b8` и прочие).

Итог: адрес, структура, ось и масштаб установлены и проверены, заводское имя
переменной — нет.

## Про ChipTuningPRO

Программа была установлена под Wine, но для этого вопроса она бесполезна:
приложенные `.b79` описывают прошивки **Нивы**. Даже полностью работающая
программа не назовёт, что лежит по адресу `0x1955B` в прошивке Kia — там
другая раскладка. Помог бы только пакет разметки под Kia или Hyundai на
M7.9.7 (в `add.ini` упомянут `B797_Huynday_Getz_1,1.b79`).
