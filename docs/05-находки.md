# Что установлено по прошивкам FBH3ID60

Всё ниже получено из трёх ваших файлов и проверено воспроизводимо:
`python3 tests/test_fbh3id60.py`.

## Идентификация блока

Строка по адресу `0x10182`:

```
EURO-3     REP.SHOP.CDA-1.6D     0261208504 1037368793 F3D6IS0H   M91B266B   FBH3ID60   391102X3350
```

| Поле | Значение |
|---|---|
| Номер блока Bosch | `0261208504` |
| Номер ПО Bosch | `1037368793` |
| Калибровка | `FBH3ID60` |
| Номер OEM (Kia/Hyundai) | `391102X3350` |
| Норма | EURO-3 |

Строка одинакова во всех трёх файлах — калибровщик её не менял.

Если найдёте DAMOS или готовый проект под номер ПО `1037368793`, он закроет
разметку целиком; искать стоит именно по этому номеру.

## Контрольные суммы — решены полностью

Таблица с `0x1FC00`, записи по 16 байт:

```
+0   u32  начальный адрес региона
+4   u32  конечный адрес региона (включительно)
+8   u32  контрольная сумма
+12  u32  ~сумма (побитовое дополнение, служит признаком валидности записи)
```

- Адрес → смещение в файле: `offset = addr - 0x800000`
- Алгоритм: **сумма 16-битных little-endian слов** по региону, 32-битный
  аккумулятор с переполнением.

Проверка: **32 записи из 34 сходятся точно во всех трёх прошивках**.
Оставшиеся две (адреса `0x00000000`–`0x00007FFF`) описывают память вне
этого дампа, во всех файлах одинаковы и пересчёту не подлежат.

Практический вывод — правленую прошивку можно готовить к заливке прямо здесь:

```bash
python3 tools/bosch_csum.py check правленая.bin
python3 tools/bosch_csum.py fix   правленая.bin -o готовая.bin
```

Проверено круговым тестом: правка байта в карте ломает ровно одну сумму,
пересчёт восстанавливает все 32.

## Форматы карт — в прошивке их два

Это была главная сложность: классический сканер Bosch находит только часть карт.

**1. С заголовком** (`nx:u8, ny:u8, X[nx], Y[ny], D[nx*ny]`) — так лежат
большинство таблиц и все двумерные кривые. Пример, проверенный вручную:
карта `0x101F4`, 16x16, ось X `6..133`, ось Y `10..150`, тело с `0x10216`.
На неё максимум ссылок из кода.

**2. Голой сеткой** — только тело, без счётчиков и осей; оси общие и лежат
отдельно. Так лежат **все три карты зажигания**. Классический сканер их
не видит в принципе — для них написан `tools/gridscan.py`, определяющий
ширину по разбросу разностей на шаге W.

## Карты зажигания

Имена и масштабы — из заводского DAMOS родственной прошивки
(см. [06-damos.md](06-damos.md)). Все байтовые и **знаковые**.

| Карта | Адрес | Размер | Сток, град | Что это |
|---|---|---|---|---|
| `KFZWOP` | `0x10529` | 11 x 16 | 0.75..45 | оптимальный угол опережения |
| `KFZW` | `0x109F5` | 12 x 16 | -0.75..42.75 | основная карта зажигания |
| `KFZW2` | `0x10AB5` | 12 x 16 | 2.25..33.75 | карта зажигания, вариант 2 |
| `KFZWMS` | `0x10935` | 12 x 16 | -24.75 (константа) | предельно поздний угол |
| `KFZWMN` | `0x14DA4` | 12 x 16 | -32.25..93.75 | минимальный угол |

`KFZWMS`, `KFZW` и `KFZW2` лежат встык: `0x10935` + 192 = `0x109F5` + 192 = `0x10AB5`.

Столбцы = нагрузка, строки = обороты. Это подтверждается и физикой, и DAMOS:
у `KFZWOP` ось X = `SNM16OPUB` (обороты, 16 точек, x40 об/мин), ось Y =
`SRL11OPUW` (нагрузка, 11 точек) — а в образе карта лежит 11 в ширину.

> **Поправка к первой редакции.** Изначально `KFZW` был определён как
> 12 x 15 по адресу `0x10A01` — детектор ширины обрезал верхние строки.
> DAMOS дал точную границу: 12 x 16 с `0x109F5`.

### Масштаб угла: 0.75 °/ед. — подтверждён DAMOS

`IGN_MAIN_11x16` в стоке при множителе 0.75:

- холостой ход / малая нагрузка: **24°**
- малая нагрузка, высокие обороты: до **45°**
- полная нагрузка, низкие обороты: **0.8–6°**

Это ровно то, что ожидаешь от исправной карты зажигания. И теперь это не
догадка: в DAMOS пересчёт для этих карт называется `zw_sb_q0p75` — знаковый
байт, квант **0.75 град KW**, диапазон -96..95.25. Обороты — `nmot_ub_q40`,
то есть **x40 об/мин** на единицу.

### Что сделал калибровщик

Относительно стока в `IGN_MAIN_11x16` добавлено **до +9 ед. (+6.75°)** в
89 ячейках из 176 — область средних и высоких нагрузок на средних оборотах.
Нижняя и левая части карты (холостой ход, малые нагрузки) не тронуты.

Разница между двумя вашими csok — ровно **+1 ед. (+0.75°)** в блоке средних
оборотов. То есть `v2` это тот же тюнинг с чуть более ранним зажиганием;
слова калибровщика подтверждаются полностью.

Посмотреть самому:

```bash
python3 tools/showmap.py --profile profiles/FBH3ID60.json \
    --name IGN_MAIN_11x16 --scale 0.75 --unit град \
    firmware/FBH3ID60_stok.bin "firmware/FBH3ID60 e2 tun csok.bin" \
    "firmware/FBH3ID60 e2 tun csok v2___.bin"
```

## Оси

Оси хранятся цепочками, вплотную друг к другу, в формате `n:u8, X[n]:u8`.
Найдены два блока:

| Блок | Адреса | Осей |
|---|---|---|
| 1 | `0x1008C`–`0x10182` | 21 |
| 2 | `0x181C1`–`0x18291` | 24 |

Первый блок упирается ровно в строку идентификации — это хороший признак
того, что цепочка разобрана до конца правильно.

**Вопрос закрыт DAMOS.** Ось нагрузки для `KFZWOP` — это `SRL11OPUW`,
11 точек, и она **шестнадцатибитная**, поэтому байтовый поиск её и не находил.
В px5ns03d она лежит по `0x14B1A`. Осей на 11 точек среди байтовых цепочек
нет именно поэтому.

## Прочие правки калибровщика

Дифф стока против csok показывает 18 изменённых областей. Кроме карт
зажигания:

- **`0x10009`–`0x10027` — таблица флагов диагностики.** Значения 0/1;
  в csok часть единиц заменена нулями, то есть отключён ряд проверок.
  Это стандартная практика при тюнинге, но знайте, что это сделано.
- Изменены таблицы около `0x1093C`, `0x11A01`, `0x14A48`, `0x14DA4`
  (16x12, u16), `0x18FD5`, `0x1949B`, `0x19653`, `0x1A6AC` (8x5, u16).
- Две кривые на 6 точек по `0x1955B` и `0x19568` — меняются и между двумя
  csok, то есть тоже относятся к зажиганию.
- `0x1FC68`–`0x1FC8F` — пересчитанные контрольные суммы двух регионов.

Полный список: `out/diff_stock_csok1.txt` после прогона `./analyze.sh`.

## Что сделал калибровщик

Полная таблица — в `out/ЧТО_ИЗМЕНЕНО.md` после прогона. Главное:

| Карта | Изменение | Смысл |
|---|---|---|
| `KFZW` | +2.25..+11.25 град, 128 из 192 ячеек | основная карта зажигания раньше |
| `KFZWOP` | +0.75..+6.75 град, 89 из 176 | оптимальный угол раньше |
| `KFZW2` | +0.75..+5.25 град, все 192 | вариант 2 раньше |
| `KFZWMS` | было -24.75 везде, стало до +11.25 | **поднят предел позднего угла** |
| `KFZWMN` | +14.25..+28.5 град | **поднят минимальный угол** |
| `KFLBTS` | 0.766..1 -> 0.844..1 | лямбда защиты компонентов беднее |
| `KFDZWKG` | +0.75..+3 град | коррекция по границе детонации |
| `ETADZW` | -2.5 % в одной точке | КПД по углу |

Плюс обнулена часть флагов диагностики в `0x10009`–`0x10027`.

Две последние строки стоит понимать ясно: `KFZWMS` и `KFZWMN` — это
ограничители, которые не дают блоку уйти в слишком поздний угол, а `KFLBTS`
задаёт обогащение для защиты катализатора и поршней на полной нагрузке.
Их сдвиг вместе с общим ранним зажиганием сужает запас по детонации.
Это не оценка работы калибровщика, а описание того, что в файле.

### Разница между двумя csok

Ровно **+0.75 град** в `KFZW`, `KFZW2` и `KFZWOP` (по 56–63 ячейки в каждой),
плюс правка двух кривых по `0x1955B`/`0x19568` и пересчёт контрольных сумм.
Слова калибровщика подтверждаются полностью.
