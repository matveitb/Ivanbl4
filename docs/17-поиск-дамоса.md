# Поиск подходящего DAMOS в чужой базе

## Почему облако не читается отсюда

Диск `cloud.mail.ru/public/RiNt/JAGmbYraM` из этой среды недоступен.
Проверено не по одному адресу:

```
cloud.mail.ru            CONNECT tunnel failed, response 403
datacloudmail.ru         000
thecloud.mail.ru         000
cloclo1.datacloudmail.ru 000
```

Статус прокси показывает причину прямо:

```
"recentRelayFailures": [{
  "kind": "connect_rejected",
  "detail": "gateway answered 403 to CONNECT (policy denial or upstream failure)",
  "host": "cloud.mail.ru:443"
}]
```

Это запрет сетевой политики среды, а не ошибка в ссылке. Ни листинг
папок через `api/v2/folder`, ни скачивание отсюда не пройдут. Значит
качает человек, а машина должна сделать так, чтобы качать пришлось
как можно меньше.

## Что именно ищем

Идентификация нашего образа (`0x10182`):

```
EURO-3  REP.SHOP.CDA-1.6D  0261208504 1037368793 F3D6IS0H  M91B266B  FBH3ID60  391102X3350
```

| Поле | Значение |
|---|---|
| Bosch HW | `0261208504` |
| Bosch SW | `1037368793` |
| Калибровка | `FBH3ID60` |
| Номер Kia | `391102X3350` |
| Блок | M7.9.7, Infineon C167, флеш 512 КБ |

Порядок приоритета при поиске по именам файлов и папок:

1. **Точное попадание.** `1037368793`, `0261208504`, `FBH3ID60`,
   `391102X3350`. Номер ПО Bosch -- самый надёжный ключ: дамосы часто
   так и называются, `1037368793.dam`.
2. **Тот же блок, то же семейство моторов.** `M7.9.7` вместе с Kia или
   Hyundai: Spectra, Shuma, Cerato, Rio, Accent, Getz, Elantra. Номера
   ПО у них соседние, `10373687xx`, `10373686xx`.
3. **Тот же блок, другой мотор.** `M7.9.7` от ВАЗ: 21114, 21124, 21126,
   Приора, Калина, Гранта; Итэлма, Январь 7.2 в связке с M7.9.7. Блок
   тот же, структура калибровок та же, имена те же -- это и даёт сдвиги.
4. **Соседнее семейство.** `M7.9`, `ME7.9.7`, `MSE7.9`. Наш px5ns03d
   отсюда.

Что качать бесполезно: всё на `ME17`, `M17.9.7`, `Simos`, `EDC`,
`Delphi MT20`, `Siemens/Continental` -- другой процессор, другая
структура, переносить нечего.

## Как проверить кандидата за секунды

```
python3 tools/calref.py firmware/FBH3ID60_stok.bin --out out/calref.json
python3 tools/damoscore.py /путь/к/скачанному/           --rank
```

`damoscore` берёт из описания подряд идущие скаляры, скользит каждой
такой цепочкой по калибровочному сегменту и принимает сдвиг, только
если выполняются оба условия сразу:

* все ячейки цепочки попадают в список адресов, которые код FBH3ID60
  действительно читает (`calref`);
* почти все значения после пересчёта укладываются в допуски, которые
  объявлены в самом описании.

Одних ссылок мало: они идут плотными участками, и внутри такого участка
десяток соседних сдвигов не различить. Одних допусков тоже мало: у
многих величин допуск -- весь диапазон байта. Вместе они дают
единственную базу; цепочки с двумя и более базами отбрасываются как
неоднозначные и в счёт не идут.

Понимает `.dam` (DAMOS/ASAP2DAM) и `.a2l` (ASAP2, с разбором
`COMPU_METHOD` и `RECORD_LAYOUT`, иначе допуск сравнивался бы с сырым
байтом и давал мусор).

## Как читать результат

```
заяк  ячеек прирост сдвигов  файл
   4     81      55       4  px5ns03d.dam
```

| Колонка | Смысл |
|---|---|
| заяк | цепочек, севших однозначно. Главное число |
| ячеек | сколько скаляров при этом получили имя |
| прирост | из них те, которых ещё нет в нашем профиле |
| сдвигов | сколько разных сдвигов понадобилось. Меньше -- ближе родство |

**Опорное число: `px5ns03d.dam` даёт 4 / 81 / 55 / 4.** Это то, что у
нас уже есть. Кандидат имеет смысл качать целиком и разбирать, если он
даёт заметно больше -- скажем, от десяти заякоренных цепочек. Настоящий
M7.9.7 от родственного мотора должен сесть на один-два сдвига и
заякорить десятки цепочек.

Достоверность метода проверяется на известном ответе: на px5ns03d
инструмент сам, без подсказок, находит сдвиг **+1** (группа отсечки
топлива, `DNSAH` садится ровно на 0x10EDA) и сдвиг **+1147** (контур
детонации). Оба были получены раньше вручную и подтверждены
дизассемблером. Это закреплено в `tests/test_damoscore.py`.

## Что делать с победителем

```
python3 tools/damoscore.py лучший.dam --out out/score.json
python3 tools/blockfind.py --damos лучший.dam --source <его образ> \
    --target firmware/FBH3ID60_stok.bin --refs out/calref.json \
    --out out/blocks.json
python3 tools/a2l_legacy.py            # пересобрать A2L с новыми именами
```

Если вместе с дамосом лежит его собственный образ -- берите и его.
`blockfind` тогда дополнительно считает, сколько констант совпало
дословно, а это независимое подтверждение сдвига: родственные
калибровки много чего не меняют.
