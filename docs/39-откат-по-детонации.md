# Откат по детонации: где он хранится и как возвращается

Вопрос владельца: где у нас откаты по детонации. Разобрано по коду
0x84EE4E..0x84EEFE (чтение кривых) и 0x84F2A2..0x84F4CA (сам контур).

## Откат -- в ОЗУ, а не в прошивке

| что | где |
|---|---|
| откат по цилиндрам | **0xF883..0xF886**, байт на цилиндр, 0.75 град на единицу |
| текущий цилиндр | 0x897D |
| средний откат | 0xF88C |
| стук в этом такте | бит 0xFD44.14 |
| счётчик до возврата | 0x89D3 + цилиндр |
| адаптивный откат по диапазонам | 0xADB7 + диапазон (0x9702) + цилиндр |

В прошивке лежат только правила: на сколько снимать угол, до какого предела
и как быстро возвращать. Сами откаты живут в ОЗУ и пропадают при выключении
(адаптивные, скорее всего, держатся, пока не снята клемма, -- это по коду
не проверено).

## Правила -- кривые по оборотам

Все читаются по индексу оборотов 0x9054. Ось 0x18208: 400, 800, 1200,
1600, 2000, 2520, 3000 ... 7000.

| кривая | адрес | куда | значение | смысл |
|---|---|---|---|---|
| `KRFKN` | 0x18F05 | 0x89C1 | 4 везде | **шаг отката: 3 град** на каждый стук |
| `KRMXN` | 0x18F15 | 0x89C3 | 16 везде | **предел: 12 град** |
| `KRVFN` | 0x18F2D | 0x89C5 | 17, 17, 25, 39, **51** (2000), 67 ... 233 | задержка возврата, тактов цилиндра на 0.75 град |
| -- | 0x18F3D | 0x89C4 | 4, 8 ... 64 | вторая задержка, при 0xFD46.14 |
| -- | 0x18EAF | 0x89B7 | 7 везде | цилиндры не расходятся со средним больше 5.25 град |
| `LKRN` | 0x18F4D | 0x89B5 | 67, 67, 60, 53 ... | |

Во всех известных прошивках эти кривые стоковые: v2M, MPower, csok, L,
Xoptim -- никто не трогал.

## Почему «тупит, потом медленно набирает»

Стук снимает 3 град сразу. Возврат идёт по 0.75 град, и каждый шаг ждёт
`KRVFN` тактов этого цилиндра. На 2000 об/мин цилиндр работает 16.7 раза в
секунду, `KRVFN` там 51 такт -- **около 3 секунд на шаг 0.75 град**. Один
стук возвращается 4 шагами, то есть секунд 12. Несколько стуков подряд --
откат 6..12 град и возврат на полминуты.

Это ровно тот рисунок, что описал владелец. Доказательством он не является:
нужен лог угла.

## Как увидеть в логе

ELM отдаёт итоговый угол (PID 0x0E), откат в нём уже вычтен. Сравнение с
`KFZW` на тех же оборотах и нагрузке показывает откат косвенно. Прямо
массив 0xF883..0xF886 можно прочитать только диагностикой с чтением памяти
по адресу (KWP2000 ReadMemoryByAddress), обычный ELM-сканер этого не
умеет.
