# 0x119E3 — это не AGR, это кондиционер

Владелец спросил про карту, которую правили оба тюнера: `KFAGRP` на
`0x119E3`, «P-составляющая регулятора рециркуляции ОГ». И сразу заметил,
что рециркуляции на этом моторе нет.

Разобрал по коду. Карты там нет вообще, а участок оказался блоком
**управления компрессором кондиционера**.

## Что на самом деле лежит на этих байтах

Читает их одна процедура, `0x8566CC`…`0x8569D6`, вызываемая из списка
задач на `0x83070C`. Сперва она считает индекс оси:

```
8567BC   mov   r12, #0x19d9        ; счётчик 8, дальше восемь точек
8567C0   movbz r13, 0xf89e         ; обороты
8567C4   calls 0x0074da            ; поиск по оси
8567C8   mov   0x98ce, r4          ; индекс лёг сюда
```

а дальше трижды берёт по этому индексу значение из **разных** таблиц,
отстоящих друг от друга ровно на восемь байт:

```
856920   mov r12, #0x19e2   ...  сравнение с 0x98D3 -> бит 0xFD56.12
85693A   mov r12, #0x19f2   ...  сравнение с 0x98D5 -> бит 0xFD56.13
856954   mov r12, #0x19ea   ...  сравнение с 0x98D4 -> бит 0xFD56.14
```

То есть это не карта 7×7 на `0x119E3`, а **ось и четыре кривые по
восемь точек** начиная с `0x119D9`. Границы читаются прямо в образе:

```
119D8  250 | 8 | 20 25 35 50 75 100 125 150 | 20 20 20 20 20 20 20 20
119F0   20 20 | 20 20 20 20 25 25 25 25 | 217 0 1 15 25 16
11A00    0 | 77 89 115 154 154 154 154 154 | 77 89 114 154 ... | 59 70 94 128 ...
```

## Чем это оказалось

Ось `20 25 35 50 75 100 125 150` при множителе 40 — это
**800…6000 об/мин**. После этого имена из дамоса подошли единым сдвигом
`+0x49A`, в том же порядке, и каждое сошлось с тем, что уже было видно в
коде:

| адрес | имя | значение | что делает по коду |
|---|---|---|---|
| `0x119D8` | `LIMTKOA` | 50 с | сравнивается с `TKOAMXN` на `0x856974`: если максимальное время выключения выставлено выше — компрессор выключается насовсем |
| `0x119D9` | `SNM08KOUB` | 800…6000 об/мин | та самая ось, дамос зовёт её «8 nmot» |
| `0x119E2` | `TKOAMNN` | 4 с | минимальное время **выключенного** состояния |
| `0x119EA` | `TKOAMXN` | 4…5 с | максимальное время выключенного состояния |
| `0x119F2` | `TKOEMNN` | 4 с | минимальное время **включённого** состояния (счётчик `0x98D5` тикает только при взведённом `0xFD56.11`) |
| `0x119FA` | `TMKOAO` | 114.75 °C | верхний порог t° ОЖ: выше — компрессор выключить |
| `0x119FB` | `TMKOAU` | −48 °C | нижний порог того же окна |
| `0x119FC` | `TNACMX` | 0.2 с | сколько держать поднятые обороты после выключения |
| `0x119FD` | `TVKOA` | 0.3 с | задержка выключения |
| `0x119FE` | `TVKOE` | 0.5 с | задержка включения: `0x98D6` считает до этого числа и взводит `0xFD56.11` |
| `0x119FF` | `VKOAO` | 20 км/ч | выше этой скорости запрет по дросселю не действует |
| `0x11A00` | `VKOAU` | 0 | нижняя граница того же окна |
| `0x11A01` | `WDKKOAN[0]` | 30.1…60.2 % | **порог дросселя, выше которого компрессор отключается** |
| `0x11A09` | `WDKKOAN[1]` | то же, вариант 1 | выбор варианта — по `0xF87A`, таблица указателей `0x12926` = {`0x1A01`, `0x1A09`} |
| `0x11A11` | `WDKKOEN` | 23.0…50.0 % | порог обратного включения (гистерезис) |

Семь совпадений подряд одним сдвигом, и каждое из них независимо видно в
коде, — это уже не выравнивание, а развязка.

## Проверка, которая не может совпасть случайно

`0xFD56.11` — «компрессор включён». Этот же бит читает совсем другая
процедура:

```
840178   jb    0xfd56.11, 0x840188
840126   mov   r12, #0x508 / r13, #0x206   ; карта 0x18508
84012E   movbz r14, 0xf89e                 ; обороты
840132   movbz r15, 0x88bd
840136   calls 0x833be0
```

Карта `0x18508` — это `KFMDKO`, «момент, потребный на кондиционер»
(данные `0x18516`, имя подтверждено дамосом точно). Момент на компрессор
подключается ровно по тому биту, который взводит разобранный блок.

## Попутно опознаны ячейки ОЗУ

| ячейка | что это | откуда |
|---|---|---|
| `0x89F3` | угол дросселя wdk, 0.390625 %/бит | сравнивается с `WDKKOAN`/`WDKKOEN`; запасное значение — кривая `0x11673` по оборотам |
| `0x881D` | скорость автомобиля, 1.25 км/ч/бит | сравнивается с `VKOAO`/`VKOAU` |
| `0x8AB4`, `0x8AB3` | температура ОЖ, 0.75 −48 | окно `TMKOAO`/`TMKOAU`, и на `0x856A54` сравнение с `TMTE` `0x1976C`, уже известным порогом продувки адсорбера |
| `0x98D8` | битовое поле состояния управления компрессором | |

## Поправка к моей же записи об оборотах

Разбор упёрся в противоречие, и оно оказалось моей старой ошибкой.

В `docs/27` записано: `0x8A9B` — «обороты делить на 40, индекс оси»,
`0xF89E` — «обороты делить на 160, грубый индекс». Деления названы
верно, вывод из них сделан обратный.

```
85EFB4   mov r12, 0xf8a0 / mov r4, #0xa0 / divu r4 -> 0xF89E   ; /160
85EFE2   mov r4,  0xf8a0 / mov r5, #0x28 / divu r5 -> 0x8A9B   ; /40
```

В поиске по осям участвует **`0xF89E`** — 14 из 22 мест, включая
`0x100F2` (`SNM16_OP`, обороты 440…6520) и нашу `SNM08KOUB`
(800…6000). Значит `0xF89E` и есть сырой индекс оси оборотов, то есть
обороты делить на 40 — а сами обороты в `0xF8A0` лежат **учетверёнными**
(0.25 об/мин на единицу).

Это подтверждается независимо, отсечкой: `NMAX` `0x14BB4` = 26800, а
отсечка на Спектре 6700 об/мин. Сходится ровно, и так же сходятся
`NMAXDV` 24000 = 6000 и гистерезис `DNMAXH` 480 = 120 об/мин.

`0x8A9B` тогда — обороты делить на 10 с насыщением на 2560 об/мин,
мелкий индекс низких оборотов; в поиске по осям он не участвует ни разу.

## Что на самом деле правили тюнеры

Ни одного байта в `0x119D8`…`0x11A00` никто не трогал. Правлены **только
пороги дросселя**:

| | `WDKKOAN[0]` | `WDKKOAN[1]` | `WDKKOEN` |
|---|---|---|---|
| сток | 30.1 … 60.2 % | 30.1 … 60.2 % | 23.0 … 50.0 % |
| csok | 18.4 … 48.4 % (все 8 точек −11.7) | 18.4 … 48.4 % | 11.3 … 38.3 % |
| startpower | 25.4 … 52.0 % | **не тронут** | 18.4 … 41.8 % |
| L | 2-я и 3-я точки подняты до 39.8 и 50.0 % | то же | 2-я и 3-я подняты до 32.8 и 43.0 % |
| MPower | не тронут | не тронут | точки с 3-й по 8-ю подняты на 1.6 % |

Оба сдвинули пороги **вниз**: компрессор кондиционера теперь отключается
при меньшем открытии дросселя. Обычная правка для слабого мотора —
разгон с включённым кондиционером становится бодрее ценой того, что
холод пропадает раньше.

И здесь же видна разница между двумя прошивками, которые в остальном
совпадают байт в байт: **csok правил все три кривые, startpower —
только две**, `WDKKOAN[1]` у него стоковый.

## Что из этого выброшено

`KFAGRP` `0x119E3` и `KFAGRI` `0x119B2` — «карты регулятора AGR».
Обе получены выравниванием чужого дамоса и обе сами помечены «не
сходится». `KFAGRP` держалась в описании только потому, что её адрес
«подтверждала» ссылка `mov r12, #0x19e2` — но эта ссылка, как теперь
видно, указывает на `TKOAMNN`, на байт раньше и совсем на другое.

Из описания они ушли, на их место встали четырнадцать записей с
русскими названиями.
