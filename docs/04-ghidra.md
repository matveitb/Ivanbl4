# Нужна ли Ghidra и что делать с C167

## Короткий ответ

**Для разметки карт Ghidra не нужна.** Карты находятся структурным и
статистическим анализом — это и делают инструменты в `tools/`. Реверс кода
нужен только для двух вещей: точно узнать *назначение* карты и найти
*масштабы пересчёта*. Всё остальное решается диффом и сканером.

Поэтому: сначала прогоните `analyze.sh`, получите разметку, заведите проект
в WinOLS. К дизассемблеру возвращайтесь, только если упрётесь.

## Важное про поддержку C167 в Ghidra

В штатной поставке Ghidra **нет** процессорного модуля для C166/C167.
Ghidra из коробки знает x86, ARM, PowerPC, MIPS, 68000, 8051, TriCore и ряд
других — C166 в этот список не входит. Чтобы дизассемблировать C167, нужен
сторонний процессорный модуль (такие есть в открытом доступе, ищите
«Ghidra C166 processor module» / `.sleigh` для C166), и качество их бывает
разным.

Альтернативы, если реверс всё-таки понадобится:

- **IDA Pro** — поддержка C166/C167 есть штатно, это исторически основной
  инструмент для таких блоков.
- **Специализированный софт под Bosch** — в среде калибровщиков ходят
  готовые проекты разметки (DAMOS, A2L) под конкретные номера ПО M7.9.7.
  Если найдёте DAMOS ровно под ваш номер прошивки (из `fwinfo.py`, строки
  `1037...`), это закроет задачу быстрее любого реверса.

Не тратьте время на освоение Ghidra с нуля ради этой задачи — соотношение
трудозатрат к результату плохое, особенно с учётом отсутствия штатной
поддержки процессора.

## Если всё же ставите Ghidra

Загрузка образа:

- **Format**: Raw Binary
- **Language**: процессорный модуль C166 (из стороннего плагина);
  если модуля нет — можно загрузить как `x86:LE:16:Real Mode` **исключительно**
  чтобы смотреть на байты и пользоваться навигацией; дизассемблер при этом
  выдаст бессмыслицу, полагаться на неё нельзя.
- **Base Address**: `0x0` — тогда адреса совпадут с нашими отчётами.
- Порядок байт — little-endian.

## Импорт нашей разметки в Ghidra

Скрипт `tools/ghidra/ImportMaps.py` переносит найденные карты в проект:

1. `python3 tools/mapscan.py firmware/stock.bin --out out/maps_stock.json`
2. В Ghidra: **Window → Script Manager**, добавить каталог `tools/ghidra`.
3. Запустить `ImportMaps.py`, указать `out/maps_stock.json`.

Скрипт создаёт для каждой карты:

- метку вида `MAP_003_018000_16x16` по адресу заголовка;
- закладку в категории `Kennfeld` с размерностью, разрядностью и оценкой;
- определённые данные: счётчики, массивы осей, массив тела карты;
- комментарий со значениями осей.

После этого по картам удобно ходить через список закладок, а перекрёстные
ссылки (если процессорный модуль работает) сразу покажут функции, которые
эту карту читают — это и есть путь к определению назначения и масштаба.

## Практический путь к масштабам без реверса

Быстрее и надёжнее, чем ковыряние в дизассемблере:

1. Возьмите известный ориентир — например, на холостом ходу угол опережения
   должен быть около 10–15°.
2. Найдите на карте зажигания ячейку, соответствующую холостым оборотам и
   малой нагрузке (левый нижний угол).
3. Подберите фактор так, чтобы сырое значение дало этот угол.
4. Проверьте, что при этом факторе вся остальная карта остаётся в
   разумных пределах (до ~40–45° на частичных нагрузках, меньше на полной).

Тот же приём работает для оборотов, температуры и нагрузки — по крайним
точкам осей.
