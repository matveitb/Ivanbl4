# Funktionsrahmen ME7.3: что он подтвердил и что дал нового

Владелец прислал `firmware/Bosch ME7.3.pdf` -- 1327 страниц, полный
Function- and Data Sheet. Это тот документ, которого не хватало.

## Подтверждено то, что было выведено самостоятельно

### Формула наполнения

ФР, функция `%BGMSZS`:

```
rlroh = ( mshfm + mste ) / ( KUMSRL * nmot )
```

`mshfm` -- расход с ДМРВ, `mste` -- поток через адсорбер, `nmot` --
обороты. Дословно то, что было вычитано из дизассемблера по 0x843A08 и
из физики. Ничего не пришлось менять.

### Константа KUMSRL

ФР даёт её прямо:

```
KUMSRL = VH [dm3] / 2578 = engine displacement volume / 2578
```

Мой вывод шёл от плотности воздуха при 0 °C и 1013 мбар:

```
KUMSRL = 1.293 * V * 30 / 1e5 = V * 3.8790e-4
```

А `1 / 2578 = 3.87897e-4`. **Совпадение до четвёртого знака.** То есть
обратный счёт рабочего объёма, которым проверялся адрес 0x1157C, был не
приближением, а той же формулой, выведенной с другой стороны.

| | сырое | объём по ФР | паспорт |
|---|---|---|---|
| FBH3ID60 (Spectra) | 79 | 1.5911 л | 1.594 |
| B103eq09 (LADA 1.5 8V) | 74 | 1.4904 л | 1.499 |
| px5ns03d | 74 | 1.4904 л | 1.5 |

## Новое: механизм подмены назван и найден

Самое важное для разбора провала.

ФР, `RLNOT`: *limp-home relative air charge rl in case of **E DK and E
LM*** -- аварийное наполнение при ошибке дросселя **или расходомера**.
Переключение реализовано в `%BGMSZS`.

Найдено в нашем образе: **0x11580**, шесть точек, u8 x0.75 %.

```
4.50   15.00   22.50   37.50   56.25   75.00
```

Доказательство адреса: px5ns03d 0x11105 + 1147 = 0x11580, а сдвиг +1147
доказан на соседнем блоке адаптации воздуха 0x1157A..0x1157F, и **разрыва
между ними нет** -- `RLNOT` начинается сразу за `MSLG`. Кривая монотонно
растёт по оборотам, форма аварийной характеристики. Одинакова во всех
тринадцати прошивках FBH3ID60.

### Почему это важно

При газе в пол реальное наполнение около **85 %** (по `RLVMXN`). В полосе
2000-2700 `RLNOT` даёт **22..37 %**. Уход туда -- это резкое падение
топливоподачи и момента. Ровно провал.

### И почему без лампы

ФР, раздел `%DHFM`:

```
Fault lamp control: 2 trps after (E lm & Z lm)
```

Лампа загорается только после **двух поездок** с подтверждённой ошибкой.
Значит кратковременная подмена проходит **без чека на панели** -- что
совпадает с тем, что владелец никакой ошибки не видит.

**Это по-прежнему версия, а не доказанный диагноз.** Проверяется замером:
`tools/expect_maf.py`, лог расхода на провале. Ниже 75 % от расчётного --
версия живая, около 100 % -- закрыта.

## Новое: имена карт, которых нет в нашем дамосе

CTP на ВАЗовской прошивке показывает раздел «Расчёт наполнения». ФР даёт
их настоящие имена:

| CTP (русский) | Funktionsrahmen |
|---|---|
| Коррекция характеристики ДМРВ | `KFKHFM` -- HFM-correction characteristic map |
| Коррекция пульсаций потока | **`KFPU`** -- pulsation characteristic map |
| Коррекция пульсаций потока 2 | `KFPUSU` -- при изменяемой геометрии впуска |
| Расход воздуха через дроссель | **`KFMSNWDK`** -- найдена, 0x15664 |
| Суммарный расход воздуха перетечек | `MSLG` -- найдена, 0x1157F |
| Мин. открытие дросселя, обеспеч. макс... | `WDKUGDN` |
| -- | `PUKANS` -- поправка пульсаций по температуре воздуха |

**`KFPU` и `KFKHFM` в `px5ns03d.dam` отсутствуют вовсе.** Это важный
вывод о самом дамосе: он от урезанной сборки, и часть воздушного тракта в
нём не описана. Значит искать эти карты придётся по коду, а не
выравниванием.

Пульсации стоит искать в первую очередь: коррекция ДМРВ по пульсациям
максимальна как раз на низких оборотах при большом открытии дросселя --
то есть ровно в той полосе, где владелец ловит провал.

## Заодно: CTP как источник адресов

Владелец открыл в ChipTuningPRO прошивку **B103eq09** -- ВАЗ 1.5 8V,
Bosch 0261207832, ПО 1037369698, M7.9.7. Этот файл лежит у нас в
`firmware/` с самого начала.

Метод на неё переносится полностью. Блок адаптации воздуха найден тем же
способом, сдвиг +852:

| адрес | имя | ВАЗ | Spectra |
|---|---|---|---|
| 0x11455 | `KUMSRL` | 74 -> **1.4904 л** | 79 -> 1.5911 л |
| 0x11453 | `CWFKMSDKA` | 1 | 1 |
| 0x11456 | `MSALLMN` | 2 кг/ч | 2 кг/ч |
| 0x11457 | `MSALLMX` | 8 кг/ч | 8 кг/ч |
| 0x11458 | `MSLG` | 3.1 кг/ч | 4.8 кг/ч |

Отсюда рабочий приём: **CTP показывает значения, мы ищем адреса.** Если
из CTP выписать числа любой карты или скаляра, найти их в
`B103eq09.bin` -- дело секунд, потому что совпадение по содержимому
однозначно. А дальше адрес переносится на Spectra выравниванием, как уже
делалось.

То есть бесплатный модуль CTP для ВАЗ работает как дамос -- не напрямую,
но через этот мостик.
